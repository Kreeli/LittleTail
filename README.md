# LittleTail

基于 **CH32V305FBP6 + ES9018K2M** 的 USB 声卡固件，用于 USB Type-C 转 3.5mm 模拟音频输出。工程使用 CherryUSB，提供 **UAC2 异步播放、48kHz / 96kHz、32bit 立体声**，并保留 CDC 虚拟串口调试功能。

## 使用建议与兼容性

**尽量在 PC 上使用本工程，当前主要在 Windows 上开发和测试。**

- 本工程依靠主机读取异步 feedback 端点，补偿实际 I2S 采样率与标称采样率的偏差。
- 在本工程的设备测试中，**Android 设备对本设备 feedback 端点的支持不佳**，可能出现水位漂移、播放异常或采样率切换问题；具体表现与系统版本、设备和播放软件有关。
- **低版本 Android 设备不支持本工程的一部分采样率设置**，可能无法识别全部采样率或正确切换。工程目前对外声明 48kHz 和 96kHz，不保证所有 Android 设备都能使用这两档。
- CDC 调试时，建议先在 VOFA 等串口工具中打开串口，再开始音频播放。播放开始后再打开 CDC 仍可能失败，这一限制尚未解决。

## 硬件与引脚

| 项目 | 配置 |
|---|---|
| MCU | CH32V305FBP6，系统时钟 144MHz，USBHS 高速设备 |
| DAC | ES9018K2M，I2S 从机，I2C 配置 |
| 外部晶振 | 8MHz HSE |
| I2S | SPI2/I2S2 主机发送：PB12 = WS，PB13 = CK，PB15 = SD |
| DMA | DMA1_Channel5，循环发送 |
| I2C | I2C2：PB10 = SCL，PB11 = SDA；7 位地址为 `0x48`，驱动传入地址为 `0x90` |
| DAC 复位 | PB14 |
| 耳放复位 | PA5 |
| 指示灯 | PC7 / PC8 / PC9，均为低电平点亮 |

### 指示灯

| 引脚 | 含义 |
|---|---|
| PC7 | DAC 锁定时亮，未锁定或状态读取失败时灭 |
| PC8 | 音频流打开时亮，关闭或 USB 总线复位时灭 |
| PC9 | 检测到 DAC 从锁定变为失锁，或触发原有音频欠载、上溢保护时亮；保持到设备重启 |

TIM1 每 10ms 置轮询标志，主循环读取 ES9018K2M 的 `0x40` 状态寄存器并更新 PC7。状态读取带超时，失败不会被计为失锁。轮询不能保证捕获持续时间短于轮询间隔的失锁事件。

## 时钟与音频同步

```text
HSE 8MHz → PLL3 80MHz → PLL3 VCO 160MHz → I2S 时钟
N = 2 × I2SDIV + ODD
Fs = 160MHz / (64 × N)
```

I2S 使用每声道 32bit 的立体声格式，每帧 64 个 BCLK。

| 标称采样率 | 分频 N | 实际 LRCK |
|---|---|---|
| 48kHz | 52 | 约 48076.92Hz |
| 96kHz | 26 | 约 96153.85Hz |

实际采样率比标称值约高 0.16%。固件根据实际分频计算基础反馈值，再用缓冲区水位进行 PID 修正，让主机调整发送速率。主机正确处理反馈，是稳定播放的必要条件。

| 项目 | 当前配置 |
|---|---|
| 播放缓冲 | 3072 个 16 位半字，即 768 帧；约 16ms @48kHz / 8ms @96kHz |
| 水位目标 | `SYNC_TARGET_MS = 8`，上限为缓冲区的一半；48kHz 约 8ms，96kHz 约 4ms |
| 安全区 | `SYNC_MARGIN_MS = 4`，达到目标水位时缩小为目标的一半，并按帧对齐 |
| PID 默认值 | `Kp = 0.001`，`Ki = 0.0004`，`Kd = 0` |
| 反馈修正限幅 | ±0.25 帧/微帧 |
| 同步节拍 | TIM2 更新中断，1kHz |

I2S/DMA 初始化后持续提供时钟，开关音频流不关闭它们；切换采样率、确实需要改变分频时会重建 I2S/DMA。USB 音频数据为小端，写入 I2S 缓冲时交换每个 32 位样点的两个半字，以便按高位先发送。

## USB 配置

| 项目 | 当前配置 |
|---|---|
| 设备类型 | CDC-ACM + USB Audio Class 2.0 复合设备 |
| VID / PID | `0x1209` / `0x0000`，当前工程中的测试配置 |
| 音频格式 | 32bit，双声道，48kHz / 96kHz |
| 音频 OUT 端点 | `0x03`，异步等时，最大包长 1024 字节 |
| feedback IN 端点 | `0x84`，4 字节，16.16 定点，单位为每微帧音频帧数 |
| 音频端点间隔 | `bInterval = 1`，高速模式下为 125µs |
| CDC 端点 | `0x81` 通知，`0x02` OUT，`0x82` IN |

## CDC 调试

使用 VOFA 或支持文本数据的串口工具查看。正常开流时，每 50ms 输出一行、共 12 列：

```text
水位,目标水位,反馈值,基础反馈值,修正量,误差,Kp,Ki,欠载次数,本tick包数,实时水位,包数累计差额
```

水位单位为 16 位半字；反馈值使用 16.16 定点；修正量输出前乘以 1e6。高速模式每微帧一包，1kHz 同步节拍下通常每 tick 约收到 8 包。

最后一列按 `8 - 本tick包数` 累加，用于辅助观察收包节拍。调度抖动、停流和重开流都会影响统计，不能只凭这一列认定发生了 USB 丢包。实时水位也会随 USB 批量写入和 DMA 连续播放呈现锯齿变化。

串口支持在线调节 PID，例如发送 `p=0.001`、`i=0.0004`、`d=0`。修改后应同时观察水位、反馈和输出波形。

## 遇到的问题与处理方法

### 间歇性的噼啪声

播放时曾出现持续数秒的噼啪声，而缓冲区水位没有明显异常。改变 ES9018K2M 的 `0x0A` 后曾感觉有所改善，但噪声仍会复现，因此不能把它作为已经确认的根因。

当前采用的关键配置是将 DAC 的 `0x0E` 从 `0xCA` 改为 **`0xAA`**：

```c
ES9018_WriteReg(0x0E, 0x8A | ES9018_MUTE_ON_LOCK);
```

保留 bit7 的 soft-start 配置，关闭 bit6 的 `soft_start_on_lock`，开启 bit5 的 `mute_on_lock`。DAC 失锁时自动静音，重新锁定后恢复输出，避免失锁期间通过 soft-start 改变输出偏置的过程。

在当前硬件测试中，恢复原有音频传输逻辑、保留这项配置及状态灯后，噼啪声已明显减少，几乎不再出现。这个结果说明 `0x0E` 是当前问题的重要影响因素，尚不能证明所有噪声都由 DAC 失锁引起，也不代表已经消除所有短暂失锁。

`0x0A` 保留为 `0x05`，没有再加入运行时自动修改该寄存器的逻辑。

### 水位突降、正弦波周期少点

排查噪声时曾尝试额外的丢帧、补静音和重对齐处理。虽然听感有所改善，但 96kHz 测试中出现了水位大幅跳变和正弦波周期点数减少的问题。

这些额外处理已撤回。当前版本恢复原有音频缓冲、PID、USB 中断和采样率切换逻辑，仅保留指示灯及 DAC 失锁静音配置。原有欠载恢复和上溢保护仍存在，PC9 用于记录它们是否触发。

### 实际采样率与主机标称值有偏差

本工程的时钟组合无法直接得到精确的 48kHz / 96kHz。解决方法是按实际 I2S 分频计算反馈值，并用水位 PID 修正。主机忽略或错误处理 feedback 时，单靠扩大缓冲区不能消除长期速率偏差。

### DAC 状态读取影响实时处理

状态读取放在主循环，定时器中断只置标志。单字节 I2C 接收在清除 ADDR 前关闭 ACK，只有清 ADDR、发送 STOP 的短临界区屏蔽音频相关中断；等待阶段允许 USB 和音频同步中断运行，并设置超时退出。

### CDC 打开顺序限制

音频关闭时先打开 CDC，再开启音频，可以持续接收调试信息；已经播放时再打开 CDC 仍可能失败。目前使用上述顺序作为调试方法，没有将该问题标记为已修复。

## 编译与使用

1. 使用 MounRiver Studio 2 打开 `LittleTail.wvproj`。
2. 检查本机工具链与工程路径设置，编译生成 ELF / HEX。
3. 通过 WCH-Link 等工具烧录到 CH32V305FBP6。
4. 连接 PC，在系统音频设置中选择设备和 48kHz 或 96kHz；需要调试时先打开 CDC。

也可以在完成 IDE 构建目录配置、并将 RISC-V GCC 和 make 加入 PATH 后执行：

```sh
make -C obj main-build
```

`tools/uac2_audit/audit_uac2.py` 可检查编译产物中的真实 USB 描述符：

```sh
python tools/uac2_audit/audit_uac2.py obj/LittleTail.elf
```

当前固件已通过编译、链接与 USB 描述符检查，并在现有硬件上进行了播放测试。生成物和本地恢复文件不纳入版本控制。
